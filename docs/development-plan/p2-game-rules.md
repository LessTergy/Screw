# P2. Детерминированная логика попытки

[Индекс и статусы](README.md)

## Цель

По допустимому выбору болта получать однозначный результат хода.

**Вход:** подтверждённый Gate P1: контракт данных и тестовое окружение. Полные игровые описания и геометрические W не требуются: механика проверяется на изолированных законченных фикстурах, включая старый домик.

**Границы:** состояния, сортировка и правила завершения; камера, реальные задержки и физика сюда не входят.

## Задачи по порядку

Каждая задача со своими тестами проверяется до использования её результата следующей задачей. Тесты управляют переходами хода явно и не зависят от реальной длительности анимаций.

1. **P2.1.** Создать независимое состояние попытки из проверенного игрового описания. Автотесты подтверждают точное начало, неизменность конфигурации и отсутствие общих изменяемых коллекций между попытками/уровнями. Проверить 2, 5 и 10 цветовых групп; логика не зависит от названий R/B/G и материала Unity.
2. **P2.2.** Реализовать назначение места: левый подходящий контейнер либо свободное место пула. Автотесты проверяют совпадение цвета, два подходящих контейнера, повторное использование места и запрет повторного снятия.
3. **P2.3.** Реализовать переполнение. При `5/5` неподходящий болт вызывает поражение без снятия; подходящий принимается контейнером. Оба случая проверяются автоматически; недопустимый ход не уменьшает крепления модуля.
4. **P2.4.** Реализовать замену контейнеров и переносы из пула. Тесты проверяют порядок поступления, поиск подходящего болта из середины пула, цепочку замен, исчерпание очереди и порядок слева направо.
5. **P2.5.** Добавить переходы хода, однократное уменьшение креплений владельца, логическую готовность к победе, терминальные состояния и сброс. Автотесты: деталь с 1 и 11 болтами, разные цвета на одной детали, один цвет на разных деталях; снятие чужого болта не освобождает владельца. Проверить повторные команды, команды во время хода/после результата и точное восстановление начала. Логическая победа не означает показ результата до завершения визуального хода.
6. **P2.6.** Сохранить логическую регрессию старого GDD §4: девять строк победного маршрута, поражение на G4 и спасение через B5. Дополнить фикстурами 2/5/10 цветов, исчерпания всех контейнеров, последнего болта в пуле и точного баланса каждого цвета. Это тесты механики; они не выдают домик или ещё отсутствующие W за готовый контент кампании.

## Приёмка и Gate

Пользователь запускает Edit Mode тесты. На фикстурах все болты учитываются ровно один раз, пул пуст при победе, освобождены только владельцы без оставшихся креплений. Старый маршрут собирает 18 болтов; G4 остаётся при поражении, B5 спасает при 5/5. Необходимые проверки 2/5/10 цветов проходят независимо от 3D-сцены и ещё не подготовленных раскладок.

**Gate:** все тесты проходят; сохраняются уникальность болтов, вместимости и неизменность состояния при недопустимом действии. Модель предоставляет порядок действий для визуального исполнения без повторного расчёта правил в UI. Зафиксировать результат Test Runner в индексе до P3.
