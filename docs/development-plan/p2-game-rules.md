# P2. Детерминированная логика попытки

[Индекс и статусы](README.md)

## Цель

По допустимому выбору болта получать однозначный результат хода.

**Вход:** подтверждённый Gate P1: контракт данных и тестовое окружение. Полные игровые описания и геометрические W не требуются: механика проверяется на изолированных законченных фикстурах, независимо от конкретной 3D-модели.

**Границы:** состояния, сортировка и правила завершения; камера, реальные задержки и физика сюда не входят.

### Контракт попытки и хода

`new LevelAttempt(source, gameplay)` сначала использует валидатор P1. Затем сохраняет независимый исходный снимок: последующее изменение DTO не изменяет ни текущую, ни повторную попытку. Цвет болта определяется его группой и `AllowedBoltPaletteIndices[groupId]`; принадлежность детали остаётся отдельным ownerId. ID болтов/деталей используются как ключи, а не позиции массивов.

`ReserveBolt(boltId)` назначает место до выкручивания и начинает один ход. Возвращаемый `BoltReservationResult` содержит:

- `Reserved` — слот занят резервом; `Turn` содержит уникальный объект хода. `Destination` содержит `ContainerIndex` и `SlotIndex`. `ContainerIndex=null` означает пул, иначе это 0/1 — левый/правый контейнер.
- `UnknownBolt` / `AlreadyReserved` / `AlreadyRemoved` / `TurnInProgress` — команда отклонена без изменения состояния и без нового места назначения/хода. Уже снятый болт нельзя выбрать заново, включая болты завершённых контейнеров. Нажатия во время хода не накапливаются.
- `PoolOverflow` — нет свободного подходящего контейнера и все пять ячеек заняты; Status становится Lost, болт не получает резерв.
- `AttemptInactive` — попытка уже завершена победой или поражением, состояние не меняется.

`PoolCount` и `AttemptContainer.ReservedCount` показывают занятую ёмкость: резерв занимает слот сразу, прибывший болт сохраняет его до автоматического переноса/завершения контейнера. `Reservations` содержит только ещё не прибывший болт. Само резервирование не уменьшает `RemainingBoltsByPart`. При полном пуле сначала проверяются подходящие контейнеры; неизвестный, повторный или заблокированный ход не вызывает поражение.

Координатор будущего P4 должен хранить полученный `Turn` и передавать его в подтверждения:

1. `ConfirmDetachment(turn)` после выхода болта из крепления: Reserved → InTransit. Ровно один раз уменьшает крепления только его владельца; `ReleasedPartId` появляется при достижении нуля. Освобождение происходит и для болта, назначенного в пул, до его прибытия.
2. `ConfirmArrival(turn)` после первоначального перелёта: InTransit → AwaitingCompletion. Снимает резерв, фиксирует поступление в пул при необходимости и полностью рассчитывает автоматическую сортировку. `turn.SortingSteps` хранит порядок визуальных действий.
3. Исполнить `SortingSteps` по порядку и дождаться удаления освобождённой детали. Логика уже содержит конечное состояние сортировки; промежуточное изображение строится по шагам, повторно вычислять маршрутизацию в UI не нужно.
4. `CompleteTurn(turn)` после всех визуальных действий: AwaitingCompletion → Completed. Снимает блокировку выбора либо переводит попытку в Won, если `IsVictoryReady` уже true.

`IsVictoryReady` означает, что все болты собраны в завершённых контейнерах, пул пуст и крепления всех владельцев равны нулю. До `CompleteTurn` последнего хода Status остаётся Active; этот флаг не является командой показать экран результата. Модель не измеряет время анимаций или падения — момент их окончания подтверждает координатор.

`CancelReservation(turn)` допустима только на фазе Reserved: освобождает точно назначенный слот без перестановки остальных, переводит ход в Canceled и снова допускает выбор. Это техническая отмена до снятия; вернуть уже снятый болт нельзя. Раньше API принимал boltId; теперь нужен объект хода, чтобы запоздалая отмена не затронула новый ход того же болта. Все подтверждения проверяют идентичность текущего хода и его фазу; чужие, старые, повторные и несвоевременные команды возвращают false без изменения состояния.

### Сортировка и сброс

Полный контейнер обрабатывается слева направо: его болты добавляются в `CollectedBoltIds`, места очищаются и берётся следующая запись общей очереди. Когда очередь пуста, `IsActive=false`, и эта позиция больше не принимает болты; сохранённый ColorGroupId не означает активность позиции.

Потом ищется первый по времени поступления подходящий болт пула для первого доступного контейнера слева направо. Неподходящий болт в начале не блокирует поиск. Ячейка освобождается без сдвига остальных; следующий пользовательский ход использует первую свободную ячейку. FIFO хранится отдельно от номера ячейки. После каждого переноса снова проверяется заполнение и цикл продолжается до устойчивого состояния.

Шаг `ContainerChange` содержит позицию, предыдущую группу, три собранных boltId и следующую группу (`null` — позиция исчерпана). `PoolTransfer` содержит boltId, исходную ячейку пула и точное место назначения. Коллекции шагов/собранных болтов доступны только для чтения. `DetachedBoltIds` и `CollectedBoltIds` позволяют проверить, что болты учитываются ровно один раз, а автоматические переносы не снимают дополнительные крепления.

`Restart()` возвращает **новый LevelAttempt** с тем же номером и исходной раскладкой: все крепления восстановлены, пул/резервы пусты, контейнеры/очередь в начальном состоянии. Вызывающий код должен заменить ссылку на текущую попытку возвращённым объектом. Старая попытка и её ходы не могут изменить новую, даже если boltId совпадает. Отмена анимаций, очистка объектов сцены и восстановление камеры остаются задачами P4; логическая модель не управляет Unity-объектами.

### Сценарная регрессия P2.6

Геометрия домика, девять строк его маршрута и обозначения G4/B5 не являются требованиями P2.6. Исторический GDD сохраняется как источник правил; реальные W и прохождения предоставленных уровней готовятся в P3/P4/P4C.

Новые сценарии используют только тестовые DTO, не читают и не изменяют исходные префабы/JSON:

- `FullPoolHasLosingAndWinningContinuations`: одинаковый префикс двух попыток приводит к пулу 5/5 и контейнеру 2/3. Шестой неподходящий болт в первой попытке вызывает Lost без снятия. Во второй подходящий болт завершает контейнер, смены освобождают пул, ранее отклонённый boltId становится допустимым, а продолжение маршрута собирает все болты и исчерпывает контейнеры.
- `LastWaitingPoolBoltMustReachCompletedContainerBeforeVictory`: единственный ожидающий болт пула не считается собранным. После замены он переходит в контейнер и всё ещё не собран до заполнения тройки; затем учитывается ровно один раз в завершённом контейнере, и маршрут продолжается до победы. Здесь «последний болт пула» означает последний ожидающий в нём болт, а не искусственное состояние со всеми снятыми болтами и несогласованной ёмкостью.
- `UnequalColorPopulationsPreserveExactCapacityThroughWholeRoute`: одна группа содержит 9 болтов, другая 3, остальные по 6; соответствующая очередь обеспечивает точный баланс. После каждого хода сохраняется вместимость по каждому цвету, в конце собраны все ID соответствующих групп. Это отдельная фикстура правил, не производственная раскладка кампании.

Каждый сценарий имеет варианты для 2/5/10 цветов. Общий помощник проверяет после подтверждённого прибытия уникальность/сохранность ID и креплений владельцев, размеры 2×3 и 5, соответствие цветов контейнеров, отсутствие оставшегося допустимого переноса из пула и равенство: собранные болты цвета + вместимость его активных/будущих контейнеров = исходное число болтов цвета. Уже существующие тесты полного прохождения, очереди, FIFO и отложенной победы переиспользованы без дублирования сценариев.

## Задачи по порядку

Каждая задача со своими тестами проверяется до использования её результата следующей задачей. Тесты управляют переходами хода явно и не зависят от реальной длительности анимаций.

1. **P2.1.** Создать независимое состояние попытки из проверенного игрового описания. Автотесты подтверждают точное начало, неизменность конфигурации и отсутствие общих изменяемых коллекций между попытками/уровнями. Проверить 2, 5 и 10 цветовых групп; логика не зависит от названий R/B/G и материала Unity.
2. **P2.2.** Реализовать назначение места: левый подходящий контейнер либо свободное место пула. Автотесты проверяют совпадение цвета, два подходящих контейнера, повторное использование места и запрет повторного снятия.
3. **P2.3.** Реализовать переполнение. При `5/5` неподходящий болт вызывает поражение без снятия; подходящий принимается контейнером. Оба случая проверяются автоматически; недопустимый ход не уменьшает крепления модуля.
4. **P2.4.** Реализовать замену контейнеров и переносы из пула. Тесты проверяют порядок поступления, поиск подходящего болта из середины пула, цепочку замен, исчерпание очереди и порядок слева направо.
5. **P2.5.** Добавить переходы хода, однократное уменьшение креплений владельца, логическую готовность к победе, терминальные состояния и сброс. Автотесты: деталь с 1 и 11 болтами, разные цвета на одной детали, один цвет на разных деталях; снятие чужого болта не освобождает владельца. Проверить повторные команды, команды во время хода/после результата и точное восстановление начала. Логическая победа не означает показ результата до завершения визуального хода.
6. **P2.6.** Закрепить общую сценарную регрессию механики на фикстурах 2/5/10 цветов: победные маршруты до исчерпания контейнеров; проигрыш и спасение из одинакового состояния 5/5; последний ожидающий болт пула до сбора завершённым контейнером; точный баланс цветов, включая неодинаковые размеры групп. Проверять промежуточные состояния и инварианты после ходов. Конкретный домик, названия его болтов и маршрут из GDD §4 не обязательны. Геометрические W и прохождения реальных уровней проверяются отдельно в P3/P4/P4C.

## Приёмка и Gate

Пользователь запускает Edit Mode тесты. На фикстурах все болты учитываются ровно один раз, пул пуст при победе, освобождены только владельцы без оставшихся креплений. Из одинаковой точки 5/5 неподходящий ход проигрывает без снятия, а подходящий запускает смену контейнеров и позволяет продолжить до победы. Болт пула считается собранным только вместе с завершённым контейнером; вместимость по каждому цвету сохраняется до конца маршрута. Необходимые проверки 2/5/10 цветов проходят независимо от 3D-сцены и ещё не подготовленных раскладок.

**Gate:** все тесты проходят; сохраняются уникальность болтов, вместимости и неизменность состояния при недопустимом действии. Модель предоставляет порядок действий для визуального исполнения без повторного расчёта правил в UI. Зафиксировать результат Test Runner в индексе до P3.
