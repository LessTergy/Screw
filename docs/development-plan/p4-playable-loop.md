# P4. Ход, анимации, падение и перезапуск

[Индекс и статусы](README.md)

## Цель

Получить первый полностью проходимый уровень на реальном Level_01, прежде чем расширять результат на всю кампанию.

**Вход:** подтверждённый Gate P3, логика P2, настоящий Level_01 с готовым игровым описанием и проверочным W из P3.6–P3.7.

Использовать сохранённые результаты по [контракту передачи P3](p3-world-and-input.md#сохраняемые-результаты-и-передача-в-p4): asset `LevelGameplayDefinition` со ссылкой на каталог P1 и существующим `LevelGameplayData`, отдельный тестовый JSON маршрута и проверенные компоненты привязок/камеры/ввода/выбора. Координатор получает описание через Inspector; W используется для тестов и приёмки, runtime не строит по нему раскладку и не ищет решение.

**Границы:** весь игровой цикл Level_01 с минимальным функциональным UI; остальные 19 уровней/переходы — P4C, окончательная обратная связь — P5.

## Задачи по порядку

1. **P4.1.** Создать координатор хода с отменой операций попытки. До подключения анимаций проверить управляемыми завершениями ожиданий: повторный ввод отклоняется, очередь нажатий не создаётся, завершение отменённой операции не меняет новую попытку. Управляемые ожидания допустимы в тестах, производственный ход затем использует реальные операции.
2. **P4.2.** При создании попытки назначить двум слотам материалов каждого белого болта цвет его группы из allowedBoltPaletteIndices; общие assets не мутируют. Подготовить реальные места двух контейнеров и пяти ячеек пула, выкручивание вдоль локальной +Z, перелёт и последовательные замены по P2. Интеграционные тесты проверяют материал/группу, счётчики, назначение, число объектов и неизменность исходных prefab/material assets после повтора. Выход из крепления отделён от прибытия в контейнер/пул; не сохранять применение цвета только в тестовом стенде.
3. **P4.3.** Подключить физику настоящих деталей Level_01. До последнего крепления деталь неподвижна; после выхода последнего падает, сталкивается только с площадкой/отделёнными деталями и удаляется через секунду. Сохранить исходную позу/масштаб; центр/физическое тело не вычислять только по общему pivot. Реальные формы коллайдеров не должны искусственно перекрывать доступ. Play Mode тесты проверяют освобождение, удаление, отсутствие сдвига закреплённых соседей; изолированная фикстура дополнительно проверяет последний болт, ушедший в пул, и 11 креплений.
4. **P4.4.** Удерживать блокировку выбора до завершения всех переносов и удаления падающей детали. Камера продолжает работать. Проверить быстрые повторные нажатия и отсутствие отложенного снятия.
5. **P4.5.** Подключить «Заново», «Повторить» и результат текущего уровня. Отмена завершает ожидания и твины, удаляет старые объекты и восстанавливает те же группы/материалы, владельцев, очередь, UI и камеру. Проверить сброс в каждой фазе, несколько сбросов подряд и завершения старых callbacks после новой попытки. Жизненный цикл DOTween контролируется всей Sequence; отмена UniTask передаётся во вложенные операции.
6. **P4.6.** Пройти настоящий Level_01 по W через реальные ввод, анимации и физику: все 9 болтов собраны, все 4 детали освобождены, победа после последнего падения. Сопоставить каждый ход с логикой P2 и повторить после сброса. На изолированном интеграционном стенде проверить переполнение/спасение, перенос из середины пула и отмену цепочки замен реальными компонентами; это не доказательство наличия этих веток на Level_01. Вводный уровень с двумя цветами не обязан позволять проигрыш; реальная ветка кампании проверяется в P4C.5.

## Приёмка и Gate

Реализация и контракт P4.1 описаны в [инструкции координатора](../levels/turn-coordinator.md). Состояния и правила переиспользуют LevelAttempt; управляемые завершения находятся только в тестах. Регистрация в Gameplay, runtime-цвета и настоящие визуальные операции подключены в [P4.2](../levels/bolt-turns.md). Результаты проверки и текущий статус ведутся в индексе.

Для изолированных проверок порядка и отмены использовать контролируемые завершения операций. Для физики и визуальной интеграции пользователь запускает Play Mode тесты с реальными компонентами; проверять факты освобождения, сохранения закреплённых модулей и удаления, а не точную случайную траекторию падения.

Пользователь проходит реальный Level_01 по его W и перезапускает в каждой фазе хода. После сброса старые callbacks не меняют счётчики/объекты новой попытки. Изолированные проверки ошибок не заменяют прохождение производственного Level_01. GDD §4 с домиком здесь не используется как геометрия.

**Gate:** автоматические проверки проходят; пользователь подтверждает полное прохождение реального Level_01, runtime-цвета, освобождение всех 4 деталей и повтор в каждой фазе. Готов первый законченный игровой сценарий. Зафиксировать результаты в индексе до P4C; переходы и готовность остальных моделей ещё не подтверждены.
