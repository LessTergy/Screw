# P3.2: коллайдер шляпки болта

[Индекс и приёмка](../development-plan/README.md) · [Привязки P3.1](level-view.md)

Общий источник — `Assets/Content/3D/Levels/Bolts/Prefabs/Bolt_07.prefab`. При добавлении коллайдера через Unity MCP подтверждено, что его используют все 20 уровней. На корне болта сохранён один включённый `BoxCollider`, `Is Trigger = false`, без Rigidbody. Настройка наследуется вложенными экземплярами, отдельные коллайдеры на Mesh и стержне не требуются.

| Параметр в локальных координатах корня болта | Значение |
| --- | --- |
| Center | ≈ (−0.0008753, 0, 0.1351834) |
| Size | (0.8, 0.8, 0.23) |
| Ось от стержня к шляпке | +Z |

Это область взаимодействия со шляпкой. BoxCollider намеренно включает углы вокруг круглого края и заполняет шлиц; точное повторение меша не требуется. По Z он занимает примерно 0.0202…0.2502, не охватывая стержень.

## Что проверяет LevelColliderTests

- Один включённый BoxCollider на корне общего Bolt_07, без Rigidbody и дочерних коллайдеров.
- Наследование center, size, enabled и isTrigger всеми девятью болтами сохранённого Gameplay и болтами всех уровней из каталога. Проверяются исходный компонент и отсутствие overrides этих свойств.
- Только примитивные, включённые, нетриггерные коллайдеры в ветке игрового уровня, без Rigidbody и исключения из стандартной raycast-маски. Проверка не задаёт количество коллайдеров деталей.
- Центральные и краевые попадания, промахи рядом со шляпкой, поверхности с обеих сторон и отсутствие боковых попаданий в стержень.

Для лучей используются локальные координаты корня каждого настоящего болта; Transform переводит их в мировые координаты с учётом положения, поворота и масштаба:

| Луч | Ожидание |
| --- | --- |
| Из Z=1 вдоль −Z при X/Y=0 | Попадание в переднюю поверхность около Z=0.25 |
| Тот же луч при X=±0.38 или Y=±0.38 | Попадание у края |
| Тот же луч при X=Y=0.38 | Попадание в угол области BoxCollider |
| Тот же луч при X=±0.42 или Y=±0.42 | Промах |
| Через центр вдоль +Z с обратной стороны | Попадание в заднюю поверхность |
| Из X=1 к X=−1 при Y=0 и Z=−0.5, −0.2 или 0 | Промах по стержню |
| Тот же боковой луч при Z=0.13 / Z=0.3 | Попадание в шляпку / промах за шляпкой |

`Collider.Raycast` проверяет только указанный коллайдер: это проверки формы, а не пользовательского выбора и перекрытия другими объектами. Обратное попадание в объём не разрешает выбор обратной стороны болта: проверка ориентации относится к P3.5.

Fixture читает сохранённый Gameplay, открывая его аддитивно только при необходимости. Уже открытая сцена должна быть сохранена. Тесты не создают геометрию, не изменяют слои, ссылки или коллайдеры и не сохраняют assets. После запуска закрывается только открытая тестами сцена; если она неожиданно стала dirty, она остаётся открытой с ошибкой проверки для сохранения изменений.

## Запуск и ручная проверка

1. Сохранить Gameplay. В обычной сцене вне Play Mode и Prefab Mode выполнить Test Runner → EditMode → `Screw.Tests.Levels.LevelColliderTests`.
2. Выполнить регрессию `LevelViewTests` и `BootstrapScopeTests`. Затем, сохранив сцены, запустить `BootstrapPipelineTests` в PlayMode.
3. Открыть Bolt_07 и включить Edit Collider: проверить охват шляпки и отсутствие стержня в объёме. В Gameplay осмотреть болты с обеих сторон и убедиться, что параметры коллайдера наследуются без overrides.

Результаты запуска тестов и пользовательская приёмка ведутся в индексе плана.

## Границы покрытия

В P3.6 отсутствие препятствий деталей исправлено в общем prefab modelbatch_lollipop_01: 8/8/9 BoxCollider вдоль трёх завитков и один на палочке. LevelColliderTests теперь требует наличие примитивов у каждой детали и их происхождение из общего model prefab. Форма, погрешности, реальное перекрытие и общий список приёмки описаны в [инструкции пространственного стенда](spatial-route.md).

Коллайдеры блокирующих деталей, их существенные просветы и ближайшие пересечения входят в [контракт P3.2](../development-plan/p3-world-and-input.md#p32-переработка-коллайдеров-по-замечаниям-пользователя). Текущие тесты шляпок не проверяют полноту геометрии перекрытий: они не заменяют контрольные лучи всей сборки и осмотр пользователем. Статус приёмки P3.2 указан только в индексе.

Требования точных треугольников, глубины шлица, MeshCollider и ShaftCollider удалены из тестов. Зависимостей от отдельных collision mesh assets больше нет. Камера, ввод, правила выбора и физическое падение этой задачей не реализуются.

API проверены через Context7 и официальную документацию Unity 2022.3: [Collider.Raycast](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Collider.Raycast.html), [исходный компонент вложенного prefab](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/PrefabUtility.GetCorrespondingObjectFromOriginalSource.html), [SerializedProperty.prefabOverride](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/SerializedProperty-prefabOverride.html). Context7 вернул общую документацию; точные контракты уточнены по этим официальным страницам.
