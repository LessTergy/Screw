# P3.2: коллайдеры Level_01

[Индекс и приёмка](../development-plan/README.md) · [Привязки P3.1](level-view.md)

**Важно:** ниже описана отклонённая пользователем реализация с MeshCollider и стержнями. Она пока остаётся в assets, но не является целевым решением и не закрывает P3.2. Актуальное задание — [переработка P3.2 в этапе 3](../development-plan/p3-world-and-input.md#p32-переработка-коллайдеров-по-замечаниям-пользователя): примитивы, у болтов только шляпки, единая настройка на корне общего prefab. По поручению пользователя сейчас изменён только план; повторять приведённую ниже настройку не нужно.

## Сохранённая геометрия

В `Assets/Content/Scenes/Gameplay.unity` на экземпляре `LevelAnchor/LevelPreview/Level_01` добавлены 22 включённых `MeshCollider`. Все имеют `Convex = false`, `Is Trigger = false`, находятся на обычном слое Default и не связаны с Rigidbody. Ground остаётся отдельной площадкой вне уровня. Общего box/capsule-коллайдера у фигуры нет.

| Узел | Коллайдер | Collision mesh |
| --- | --- | --- |
| Каждая из 4 деталей в `Assembly/Model` | MeshCollider на узле детали | Тот же `sharedMesh`, что у MeshFilter детали |
| Каждый из 9 `Bolts/Bolt_.../ShowTrans/TurnTrans/Mesh` | MeshCollider головки на узле Mesh | `Assets/Content/Settings/Levels/Colliders/Screw004_Head.asset` |
| Дочерний `Mesh/ShaftCollider` каждого болта | MeshCollider стержня | `Assets/Content/Settings/Levels/Colliders/Screw004_Shaft.asset` |

`ShaftCollider` имеет локальные Position/Rotation = 0, Scale = 1. Остальная иерархия, трансформации, MeshFilter, материалы и привязки P3.1 сохранены. Исходный prefab не получает Apply; оригинальные meshes, JSON и каталог не изменяются.

Два новых collision mesh получены из треугольников исходного `Assets/Content/3D/Levels/Bolts/Meshes/Screw004.asset`. Треугольник относится к головке, когда Y всех трёх его вершин в локальных координатах исходного меша не меньше `0.02265`; остальные относятся к стержню. Это калибровка конкретного Screw004: основание головки находится около Y=0.02271. В головке 512 треугольников, в стержне 170; объединение точно воспроизводит все 682 исходных треугольника без добавленных крышек, растягивания или заполнения углубления шлица. Неиспользуемые вершины удалены из каждой копии. При смене исходного меша эту калибровку нужно проверить заново.

Поворот визуального Mesh по X=90° сохраняется: его локальная +Y совпадает с локальной +Z болта. Поэтому головка и её шлиц сохраняют правильное положение при обоих направлениях болтов. На исходный Screw004 не требуется включать Read/Write: collision meshes сохранены отдельными читаемыми assets; чтение исходных вершин выполняется только редакторскими тестами.

## Контрольные лучи

Координаты заданы относительно Level_01 при сохранённых нулевых Position/Rotation и единичном Scale внешнего LevelPreview. Для осмотра используются временные камеры; игровая камера не перемещается. Кадрирование и орбитальное управление относятся к P3.3.

Передняя точка наблюдения — `(0, 2, -24)`, задняя — `(0, 2, 24)`. Направление луча — в центр `bounds` коллайдера указанной головки. Дальность — 60; учитываются и детали, и болты, триггеры игнорируются.

| Целевая головка | Видна первой с этой стороны | Ближайшая поверхность с противоположной стороны |
| --- | --- | --- |
| boltId 0 | Передняя | Головка boltId 2 |
| boltId 1 | Передняя | Деталь partId 0 |
| boltId 2 | Задняя | Головка boltId 0 |
| boltId 3 | Передняя | Деталь partId 1 |
| boltId 4 | Задняя | Головка boltId 3 |
| boltId 5 | Передняя | Деталь partId 2 |
| boltId 6 | Задняя | Деталь partId 2 |
| boltId 7 | Передняя | Деталь partId 3 |
| boltId 8 | Задняя | Деталь partId 3 |

Дополнительные точки: `(0,18,-18)` и `(0,-12,-24)`. В обоих случаях головка 0 — ближайшее пересечение своего луча. Луч к головке 2 перекрывают соответственно детали 2 и 1. Это фактические перекрытия модели, а не навязанная схема зависимостей.

Для проверки вогнутых просветов лучи направлены вдоль мировой +Z из Z=−24:

| X, Y | Чей bounds пересекается, но поверхность отсутствует | Реальная следующая поверхность |
| --- | --- | --- |
| −2.9065, 0.6504 | Деталь 0 | Деталь 1 |
| −1.6243, 0.7636 | Деталь 1 | Деталь 2 |
| −0.58416, 2.72688 | Деталь 2 | Деталь 0 |
| −3.568, −0.8528 | Деталь 0 | Фон |

Шлиц проверяется отдельными лучами в локальной системе визуального Mesh: из `(0,0.1,0)` и `(0.015,0.1,0.015)` вдоль −Y. Первый пересекает дно шлица около Y=0.03780564, второй — верхнюю поверхность около Y=0.04182862. Боковой луч из `(0.1,0.005,0)` вдоль −X пересекает стержень, но не головку.

## Повторная проверка

1. Сохранить сцены. В Test Runner → EditMode запустить `Screw.Tests.Levels.LevelColliderTests`, затем регрессию `LevelViewTests` и `BootstrapScopeTests`.
2. `LevelColliderTests` читает сохранённый Gameplay и проверяет его временную копию. Только коллайдеры копии переводятся на временный слой 31 для изоляции raycast; настройки Layers проекта не меняются. Слой 31 должен быть свободен среди загруженных коллайдеров. Копия уничтожается, а открытая тестом сцена Gameplay закрывается без сохранения. Тест не строит подменную геометрию, не создаёт production-colliders и не исправляет сцены.
3. В Gameplay выбрать детали по очереди, включить Gizmos и осмотреть MeshCollider в Inspector: контур должен повторять вогнутые формы. У болтов осмотреть Mesh и ShaftCollider с двух сторон, сверху и сбоку; головка не должна включать стержень, шлиц не должен быть залит плоскостью.
4. Запустить `Screw.Tests.Bootstrap.BootstrapPipelineTests` в PlayMode: настоящая сцена с коллайдерами должна сохранять рабочие привязки, DI и restart. Сначала сохранить работу: тест меняет загруженные сцены.

Болты сейчас не выбираются нажатием: пользовательский ввод и проверка ориентации головки подключаются в P3.4–P3.5. В P3.5 нужно переиспользовать эти же коллайдеры и ракурсы. MeshCollider на Mesh — цель головки; ShaftCollider и детали — блокирующие поверхности. Нельзя отфильтровать препятствия из raycast-маски и выбирать головку за ними.

Это статические query-colliders P3. Для динамического падения в P4 невыпуклые MeshCollider нельзя просто подключить к некинематическому Rigidbody: потребуются совместимые физические коллайдеры и управление временем жизни точной геометрии выбора. Преобразование всей вогнутой детали в один Convex для выбора заполнит просветы и нарушит проверки P3.

## Документация API

Проверено через Context7 по официальному [руководству Unity о MeshCollider](https://docs.unity3d.com/Manual/mesh-colliders-introduction.html); ограничения статической/кинематической вогнутой геометрии и её односторонние грани учитываются. Сигнатуры подтверждены reflection в установленной Unity 2022.3.62f3 и её официальной документацией: [MeshCollider.sharedMesh](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/MeshCollider-sharedMesh.html), [Mesh.vertices](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Mesh-vertices.html), [PhysicsScene.Raycast](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/PhysicsScene.Raycast.html).
