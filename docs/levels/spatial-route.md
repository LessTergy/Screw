Исправлены тестовые данные повреждённого JSON и фоновое освещение Gameplay для читаемости задней стороны. [Результаты и границы проверки](p3-verification.md). Производственное описание не ссылается на W.

## Пространственный стенд

LevelRouteData, LevelRouteSession и LevelRouteWindow находятся в редакторской сборке. JSON версии 1 хранит номер уровня, FOV/aspect, относительные LevelRoot позиции/повороты камеры и viewport-точки всех девяти шагов. Чтение отклоняет повреждённые/повторные поля, чужой номер/версию, неполные и повторные ID, нечисловые параметры, неверную проекцию и точки вне viewport.

LevelRouteSession использует существующие LevelView, OrbitCamera и BoltSelection. Он восстанавливает проекцию и начальное кадрирование, затем задаёт углы через OrbitCamera.Rotate. Позиция и поворот должны совпасть с записью: поза вне доступной орбиты вызывает ошибку до снятия. BeginPointer/UpdatePointer камеры доступны для воспроизведения того же пути PointerGesture → Tapped → BoltSelection; отдельного обработчика выбора в стенде нет.

После подготовки шага правильный Selected скрывает только выбранный болт. Владелец скрывается, только когда сняты все ID из исходного part.BoltIds. Неверный ID не продвигает маршрут и ничего не скрывает. Стенд хранит набор снятых ID, без контейнеров, сортировки, физических тел и второй модели игрового хода. Dispose восстанавливает объекты и настройки камеры; остановка Play Mode и выгрузка сцены закрывают оконную сессию.

Сохранённый W записан с FOV=60°, aspect=9/16, near=0.3, far=1000. Поле camera JSON содержит только FOV/aspect по контракту плана; clip planes берутся из камеры Gameplay. Позы получены штатной орбитой, без направленного LookAt на каждый болт. Записанные жесты проверены при подготовке и повторном воспроизведении через Unity MCP вне Play Mode. ## Препятствия деталей

При подготовке W обнаружено отсутствие collider у всех четырёх деталей сохранённого Gameplay. Общий источник исправлен через Unity MCP: `Assets/Content/3D/Levels/Models/modelbatch_lollipop_01/prefab/modelbatch_lollipop_01.prefab`. Геометрия/материалы/трансформации и GUID сохранены; Gameplay наследует новые компоненты.

Палочка использует один BoxCollider с center=(0,0,0), size=(0.07,0.295,0.035). Для завитков вручную заданы короткие повёрнутые BoxCollider вдоль полос: raspberry — 8, lemon — 8, mint — 9. Они находятся в дочерних SelectionBlocker_XX, локальные масштабы единичные. Ширина полосы collider — 0.045 / 0.048 / 0.048, глубина — 0.07; последовательные сегменты слегка перекрываются. Составные полосы сохраняют внутренние просветы после снятия соседних владельцев. Погрешность есть на округлых краях, скошенной глубине и концах полос; точное воспроизведение render mesh не является контрактом. Нет MeshCollider, Rigidbody или генератора по полигонам. В сборке уровня 35 BoxCollider: 26 на деталях и 9 на шляпках. Производительность на устройстве не измерялась.

Проверка реального перекрытия: из нижней позы yaw=0°, pitch=270° головка boltId=3 обращена к лучу, но закрыта палочкой ownerId=3. Выбор отклоняется; после скрытия только палочки тот же луч выбирает boltId=3. Этот случай включён в LevelRouteTests.

## Подготовка игрового описания

LevelGameplayDefinitionUtility.Build применяет `g = floor(j/3) % N` к позициям переданного W. Контейнерные записи — `k % N`. Палитра источника сохраняет порядок. Для Level_01 получены P=[1,2], yellow IDs=[0,1,2,6,7,8], blue IDs=[3,4,5], ContainerGroups=[0,1,0]. Первые две записи активны, последняя составляет общую очередь.

Меню `Tools → Screw → Levels → Create Level 01 Gameplay` создаёт asset из сохранённого W и каталога, проверяя его через LevelDataValidator. Существующий asset не перезаписывается. Для готовой проверки повторно создавать его не нужно. Сохранённый asset читается через ReadSource с проверкой соответствия номера и цветовых групп источнику. Runtime-цвета, контейнеры и перелёты подключены в [P4.2](bolt-turns.md).

## Общая проверка этапа P3

1. Сохранить рабочие сцены, выйти из Prefab Mode. Дождаться компиляции без ошибок Console. Новых ссылок Inspector назначать не требуется; asset и JSON уже созданы.
2. В Test Runner → EditMode запустить всю Screw.EditMode.Tests. В неё входят PointerGestureTests (22 случая), OrbitCameraTests, LevelColliderTests, LevelViewTests, BootstrapScopeTests и LevelPreparationTests (32 случая). Последние проверяют границы/повтор цикла для 5/10 цветов, неверные W/палитры/B, исходы каждого хода P2, победу с пустым пулом, сохранённое описание и повторный импорт. Старые проверки P1/P2 также должны пройти.
3. В Test Runner → PlayMode выполнить BoltSelectionTests (24 случая), LevelRouteTests (4 случая), BootstrapPipelineTests и LevelReaderPlayerTests. Тесты маршрута редакторские по доступным API, но выполняются в Play Mode; их отдельная assembly ограничена UNITY_EDITOR. LevelReaderPlayerTests остаётся в прежней сборке с возможностью запуска в player. Bootstrap/маршрут переключают загруженные сцены. Ожидается отсутствие Failed и неожиданных ошибок Console.
4. Запустить Bootstrap → Gameplay. Проверить полный оборот камеры по обеим осям, оба полюса, перевёрнутое положение, кадрирование и сброс. Тап по видимой головке пишет один `Selected bolt <Id> (owner <OwnerId>).`; с P4.2 принимаемый ход запускает реальные анимации. Деталь, фон, обратная сторона, drag, отмена и перекрывающий UI не дают успешного выбора. При другом ближайшем болте выбирается именно он, если его головка обращена к камере.
5. Заново запустить свежий Gameplay и установить Game view 9:16. В Play Mode открыть `Tools → Screw → Levels → Level 01 Route`, нажать `Begin route`: стенд временно отключает GameplaySession, сохраняя настоящие ввод/выбор P3. Для каждого шага нажать `Prepare next: manual tap`, затем вручную нажать указанную головку в Game view по таблице выше. Неверный болт не продвигает маршрут. Проверить, что владельцы скрываются после шагов 3/5/7/9 и остальные детали до этого остаются на месте. `Replay next: recorded pointer` воспроизводит сохранённую точку тем же вводом. Итог: `Route complete`, девять снятых болтов и четыре скрытых владельца.
6. Нажать `Restore level / end route`: все болты/детали возвращаются, камера восстанавливается. Повторить начало маршрута; затем проверить остановку Play Mode и перезапуск Gameplay, отсутствие старых подписок и повторных сообщений. Во время активного стенда не запускать другие тесты.
7. В Prefab Mode осмотреть составные коллайдеры завитков и палочки, особенно внутренние просветы после скрытия соседних частей и края полос. Проверить реальные перекрытия со всех сторон. В Inspector готового Level_01_Gameplay проверить ссылку на каталог, LevelNumber=1, группы 6/3 и ContainerGroups=[0,1,0]. Падение, перелёты и отображение цветных контейнеров относятся к P4.
8. На устройстве повторить касание/drag/UI, полный обход камеры, доступность небольших головок и отзывчивость на Level_01. Оконный стенд W доступен в Editor; runtime-выбор работает через тот же BoltSelection.

Результаты проверки и пользовательская приёмка P3 зафиксированы в индексе плана. Текущее развитие производственного хода описано в P4; старый пространственный стенд остаётся отдельной проверкой геометрии.
