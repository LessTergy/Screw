# Пайплайн генерации и импорта уровней

Состояние на 09.11.2026. Пайплайн создаёт черновики новых фигур. Порядок и состав основной кампании описаны отдельно в [контракте кампании](../game-design/campaign.md).

Целевые числа деталей, болтов и цветов и варианты моделей для первых пяти черновиков собраны в [плане баланса](../game-design/generated-level-balance.md).

## Согласование референса и модели

1. Сгенерируй несколько референсов по заданию уровня. Покажи пользователю варианты, их силуэты и предполагаемое деление на игровые детали. Дождись выбора и явного одобрения референса перед моделированием.
2. Собери модель по самому одобренному изображению. До показа поставь рендер Blender рядом с референсом в близком ракурсе и масштабе. Сверь силуэт, пропорции крупных деталей, скругления, цветовые границы и характерные отметки. Поправь расхождения, затем проверь меши, стыки, направления креплений и повторный импорт GLB. Оставь Blender открытым на модели для осмотра.
3. Дождись отдельного явного одобрения модели. Замечания к сборке исправляй в Blender и снова передавай модель на осмотр. При смене силуэта вернись к согласованию референса.
4. После одобрения модели передай пакет в импорт Unity. Для запуска агентом через Unity MCP действует требование прямого запроса из [AGENTS.md](../../AGENTS.md). После импорта проверь маршрут и затем проведи ручную проверку игры.

### Визуальный эталон для новых моделей

Пользователь одобрил обновлённый будильник по варианту C. Используй эту пару для калибровки стиля и точности переноса. Силуэт и пропорции каждой новой фигуры бери из её собственного одобренного референса.

- [Концепт, вариант C справа](../../ArtSource/AlarmClockCReference/Reference-ABC.png) и [рендер модели с близкого ракурса](../../ArtSource/AlarmClockCReference/Preview-0001.png).
- [Исходник Blender](../../ArtSource/AlarmClockCReference/AlarmClockCReference.blend) и [отчёт проверки сетки](../../ArtSource/AlarmClockCReference/MeshValidationReport.json).

В будильнике крупные детали читаются по форме и стыкам. Подставка расширяется книзу, жёлтые колокола остаются куполами, обод широкий и сиреневый, на циферблате ровно 12 отметок. Стрелки со ступицей образуют один объём под центральный болт. Их глубина выбрана под три внутренних прямоугольных коллайдера. Скрытую сторону корпуса восстановили по одному виду. Одобрение относится к внешнему виду в Blender. Посадку болтов, коллайдеры и разборку в Unity проверяют после импорта.

## 1. Модель в Blender

Проверенный набор инструментов включает Blender 5.2.3 LTS, дополнение MCP for Blender и сервер `mcp-for-blender`, зарегистрированный в Codex как `blender`. Для авторинга можно использовать Blender MCP или обычные инструменты Blender. На этапе импорта агент не нужен.

1. Задай тему, число снимаемых деталей, болтов и целевое число цветов. Применяй [промт A](modular-low-poly-generation-prompt.md#промт-a-генерация-составной-модели) для формы и проверки сетки. Делай крупные объёмные детали с читаемыми стыками и простыми коллизиями.
2. Собери `Assembly/Model` из непосредственных детей с отдельными мешами. Создай непосредственные дочерние маркеры креплений в `Assembly/Bolts`. Присвой каждому маркеру ID, владельца и направление головки вдоль локальной оси `+Z` в Blender.
3. Проверь замкнутость и ориентацию сетки каждой детали, вырожденные грани, самопересечения и взаимное проникновение деталей. Повтори проверки на заново импортированном экспорте. Проверь фактические позиции и направления маркеров.
4. Сохрани пакет в `ArtSource/<ModelName>`. Оставь исходник `.blend` и превью рядом с экспортом. Для Unity экспортируй самодостаточный GLB с одной непустой сценой. В Blender включи экспорт активной сцены. Материалы, изображения и буферы должны содержаться в самом GLB.

Вход импортёра — ровно один `.glb` и `ModelManifest.json`. Для манифеста версии 1 поле `transformCoordinates` имеет значение `Blender right-handed, Z up; quaternion WXYZ`. Укажи `modelName`, SHA-256 исходного GLB, ID, имена, пути, число треугольников и список креплений каждой детали. У каждого болта укажи ID, `ownerId`, путь и `outwardAxis: "+Z"`. Сохраняй `MeshValidationReport.json` с результатами проверки экспорта и тем же SHA-256. Импортёр сверяет его хеш, если отчёт присутствует.

## 2. Импорт в Unity

Проект использует Unity 2022.3.62f3 и glTFast 6.14.0, зафиксированный в [манифесте пакетов](../../Packages/manifest.json). Для подготовки примитивных коллайдеров установи [локальные инструменты CoACD](../../Tools/Colliders/README.md), если их ещё нет на рабочей машине.

1. В обычной сцене вне Play Mode и Prefab Mode выбери **Tools → Screw → Levels → Import Generated Level**. Укажи папку пакета.
2. [Импортёр](../../Assets/Content/Scripts/Editor/Levels/GeneratedLevelImportUtility.cs) проверит манифест и SHA-256, загрузит геометрию, проверит число треугольников и посадочные направления. Он подставит общий prefab болта на место каждого маркера и подготовит внутренние примитивные коллайдеры деталей. Локальная ось `+Z` маркера в Blender после экспорта становится `+Y` импортированного узла. Импортёр преобразует её в `+Z` игрового болта и проверяет направление по поверхности владельца.
3. Импортёр найдёт геометрический маршрут W и воспроизведёт его через существующий механизм выбора болтов. Из W вычисляются цветовые группы и очередь контейнеров. Если маршрут обрывается, ошибка содержит ID оставшихся болтов.
4. При успехе в `Assets/Content/GeneratedLevels/<ModelName>-<hash>` появятся модель, prefab уровня и `Level_View.prefab`, отдельный каталог черновика, `Level.json`, `Level_Gameplay.asset`, `Level_Route.json` и `ImportReport.json`. Повторный импорт того же пакета переиспользует эту папку. При ошибке инструмент удаляет созданную временную папку, а причину показывает в Console.

Если экспорт Blender содержит дополнительные пустые сцены, импортёр удаляет их из импортируемой копии. В отчёте сохраняются SHA-256 исходного GLB и SHA-256 копии, которую получила Unity. Исходный пакет остаётся в `ArtSource`.

Текущий черновик использует номер 1 в собственной копии каталога и два цвета из палитры проекта, индексы `[1, 2]`. Этот номер служит для проверки. Настройка палитры под уровень и публикация в выбранный слот кампании требуют отдельных изменений. Импорт геометрии, подготовка метаданных, раскладки и маршрута выполняются локально без вызовов ИИ.

## 3. Проверка в игре

Первый контроль — `ImportReport.json` со статусом `prepared` и числом воспроизведённых шагов, равным числу болтов. Этот результат подтверждает геометрический маршрут. Для ручной приёмки сыграй уровень с обычными вводом, сортировкой и физикой. Проверь попадания по головкам, выход деталей из сборки, победу и повторную попытку.

Уровень 1 кампании использует модель «Черника со сливками». [Отчёт импорта](../../Assets/Content/GeneratedLevels/PopsicleBlueberryCream-7b92d1f581ed/ImportReport.json) фиксирует 4 детали, 46 коллайдеров и 9 воспроизведённых шагов. Модель котика подготовлена в отдельном каталоге черновика с 8 деталями и 21 шагом. [Отчёт импорта котика](../../Assets/Content/GeneratedLevels/CalicoCatReferenceModel-bf7972dd715a/ImportReport.json)

Полное прохождение, падение деталей и повторная попытка на новых моделях требуют ручной проверки в Unity.
