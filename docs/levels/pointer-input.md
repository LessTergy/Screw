# P3.4: нажатие, перетаскивание и UI

[Индекс и приёмка](../development-plan/README.md) · [Орбитальная камера](orbit-camera.md)

В P4.3.1 распознанный drag вращает уровень при неподвижной камере. Порог, отмены, перехват UI и единственный Tapped сохраняются; второй обработчик ввода не добавлен. Ожидание удаления детали с доступным drag и закрытым выбором болтов относится к P4.4.

Ввод обрабатывает существующий OrbitCamera. PointerGesture распознаёт один жест независимо от Unity Input; один и тот же код используется для ЛКМ и касания. Нового компонента сцены не требуется. Screw.Runtime ссылается на сборку UnityEngine.UI уже установленного пакета uGUI для EventSystem и raycast.

## Правила жеста

- Нажатие начинается только внутри pixelRect камеры и вне UI. Mouse использует pointerId = −1, касание — свой fingerId.
- Пока расстояние от точки начала меньше Drag Threshold Pixels, уровень не вращается. По умолчанию порог равен 10 экранным пикселям, он доступен в Inspector OrbitCamera. Ровно на пороге начинается drag; сравнивается двумерное расстояние, а не сумма движения между кадрами.
- Первый шаг drag передаёт всё смещение от точки начала, последующие — только новое движение. Свободная орбита P3.3, чувствительность и кадрирование сохраняются.
- При отпускании жест ниже порога выдаёт ровно одно событие OrbitCamera.Tapped(Vector2 screenPosition). Повторное отпускание ничего не выдаёт. Отдельной логики долгого удержания нет.
- После начала drag тап запрещён, даже если указатель вернулся к точке начала. Смещение в момент отпускания тоже проверяется: отсутствие промежуточного Move не превращает drag в тап.
- Попадание на UI или выход за viewport отменяет жест целиком. Возвращение в игровую область с удержанием его не возобновляет; требуется новое нажатие.
- TouchPhase.Canceled, смена pointerId, потеря фокуса, пауза приложения, отключение компонента и ResetOrbit отменяют незавершённое нажатие без Tapped.
- Несколько касаний отменяют текущий жест; ввод остаётся подавленным до отпускания всех пальцев. Во время касаний мышь не обрабатывается, поэтому её симуляция не дублирует тап или вращение.

На Tapped подписан [BoltSelection из P3.5](bolt-selection.md): он проверяет ближайшую поверхность и ориентацию шляпки через игровую камеру. Подписка управляется сроком жизни Gameplay scope. Нажатия не накапливаются в очередь; снятие болта остаётся P4.

## Перехват UI

На начале, движении и отпускании выполняется свежий EventSystem.RaycastAll по текущей экранной позиции. Используются повторно PointerEventData и список результатов. Проверка не зависит от того, успел ли UI Input Module обработать этот кадр.

Результаты физических PhysicsRaycaster/Physics2DRaycaster не считаются UI; стандартные GraphicRaycaster и PanelRaycaster блокируют ввод. Поэтому наличие world-collider не запрещает будущий выбор болта. При отсутствии EventSystem UI-блокировки нет; проверка viewport остаётся.

Для перехвата настоящий UI должен быть настроен штатно: EventSystem и соответствующий raycaster, активная кнопка/графика с включённым Raycast Target либо интерактивный элемент UI Toolkit. Прозрачная uGUI-графика с Raycast Target тоже перехватывает ввод по правилам Unity. Эта задача не создаёт игровой HUD.

## Автотесты и ручная приёмка

1. В Test Runner → EditMode выполнить Screw.Tests.Levels.PointerGestureTests: ожидаются 22 Passed. Проверяются мышь/касание, граница 10 px, диагональ, накопление смещения, отпускание без Move, отмена, UI на начале/движении/отпускании, смена указателя и отсутствие второго тапа.
2. Выполнить OrbitCameraTests, LevelViewTests, LevelColliderTests и BootstrapScopeTests. Модельные тесты передают признак блокировки явно; они не подменяют проверку настоящего UI-raycast.
3. В Gameplay нажать ЛКМ и двигаться меньше порога: камера остаётся неподвижной. Пересечь порог: начинается свободное вращение. Отпустить и нажать снова: новый жест работает независимо от предыдущего.
4. Для проверки UI использовать тестовую Canvas/Button с GraphicRaycaster и EventSystem: начало над кнопкой и выход наружу не вращают камеру; начало снаружи и заход на кнопку отменяют вращение до нового нажатия. UI должен продолжать получать свои обычные события. Выход за границы игрового viewport проверяется так же.
5. Во время удержания переключиться в другое приложение и вернуться: отпускание не возобновляет жест. На устройстве проверить TouchPhase.Canceled/паузу, второй палец, отпускание всех пальцев и новое одиночное касание. Device Simulator не проверяет настоящий multitouch.
6. Корректный тап по доступной головке передаётся в P3.5 и пишет выбранный ID в Console. Перетаскивание и отменённый жест не должны приводить к такому сообщению; болт пока не выкручивается. Сначала сохранить сцены, затем выполнить BootstrapPipelineTests в PlayMode для регрессии запуска и перезапуска.

Результаты и статус приёмки ведутся только в индексе плана.

## Источники API

Context7 вернул официальную документацию Unity 2022.3 о [touch phases и fingerId](https://docs.unity3d.com/2022.3/Documentation/Manual/MobileInput.html) и [UI EventSystem/raycaster](https://docs.unity3d.com/2022.3/Documentation/Manual/UIE-faq-event-and-input-system.html). Точные сигнатуры и наследование уточнены по официальным справочникам [EventSystem.RaycastAll](https://docs.unity3d.com/Packages/com.unity.ugui@1.0/api/UnityEngine.EventSystems.EventSystem.html) и [Physics2DRaycaster](https://docs.unity3d.com/Packages/com.unity.ugui@1.0/api/UnityEngine.EventSystems.Physics2DRaycaster.html). Имя сборки UnityEngine.UI проверено по установленному uGUI 1.0.0.
