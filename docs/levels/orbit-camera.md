# Вращение уровня и кадрирование — P4.3.1

[Индекс и приёмка](../development-plan/README.md) · [План P3](../development-plan/p3-world-and-input.md)

По уточнению пользователя 04.11.2026 осмотр вращает сам уровень при неподвижной камере и постоянной мировой гравитации. Реализация P4.3.1 переиспользует существующий компонент и его API; принятая история прежней орбиты камеры сохранена в индексе. Контакты и независимые динамические тела подключены в P4.3.2; [удаление целиком ниже кадра](part-physics.md) — в P4.3.3. В P4.4 ожидание удаления блокирует новый ход и победу, сохраняя этот же обработчик вращения доступным во всех фазах.

`Screw.Levels.OrbitCamera` остаётся на существующем экземпляре Main Camera в Gameplay. Ссылка Level Root через Unity MCP назначена на **LevelView.transform (LevelPreview)** — общий владелец исходного Level_01, Model и Bolts. Runtime не создаёт новый pivot или второй обработчик ввода. Исходный prefab и экспортные локальные позы не меняются; внешняя обёртка вращается вокруг вычисленного центра. Камера, UI и Ground находятся вне этой сборки.

## Поведение

- Оба угла сборки проходят полный круг без угловых ограничений, включая переворот. Позиция и поворот камеры не меняются от drag; направление Physics.gravity также сохраняется. У закреплённых Model/Bolts сохраняются исходные локальные позы относительно сборки.
- ЛКМ с перетаскиванием или один движущийся палец вращают сборку после порога 10 px. Движение на длину короткой стороны viewport соответствует 180°. Несколько касаний отменяют жест до отпускания всех пальцев; симуляция мыши не дублирует касание. UI и выход за viewport отменяют текущий жест.
- Автоповорота, инерции и пользовательского зума нет. При изменении aspect/FOV обновляются расстояние и кадрирование фиксированной камеры, текущие углы сборки сохраняются. Камера смотрит вдоль мировой +Z без крена: мировой низ соответствует низу экрана.
- Первый FrameLevel фиксирует центр/охватывающую сферу по Renderer.bounds полной фигуры, без Ground/UI, и исходную мировую позу обёртки. Расстояние учитывает меньший горизонтальный/вертикальный угол обзора, near clip и Framing Padding = 1.15. Повторный FrameLevel использует исходные центр/радиус и восстанавливает старт, не пересчитывая их по оставшимся или перемещённым деталям. Новый экземпляр после загрузки получает собственный snapshot.
- Стартовые углы сборки в Gameplay: yaw = 0°, pitch = −15° (нормализованный Pitch = 345°). Поворот — Quaternion.Euler(pitch, yaw, 0) относительно исходной мировой ориентации обёртки. Позиция обёртки пересчитывается вокруг общего центра; её масштаб и локальные Transform исходного префаба сохраняются.
- ResetOrbit отменяет текущий жест, восстанавливает стартовые углы/позу и кадрирование. Повторный вызов даёт тот же результат без накопления смещений.

FrameLevel требует перспективную камеру и хотя бы один Renderer уровня. Обязательная ссылка Level Root назначается явно. Runtime не ищет LevelView или камеру в сцене и не создаёт игровой контент.

## API для следующих задач

- Rotate(Vector2 deltaDegrees) применяет приращение обоих углов без ограничений. Yaw и Pitch нормализованы в диапазон [0, 360) только для численной устойчивости; это не останавливает вращение после полного круга.
- ResetOrbit() восстанавливает стартовую позу после инициализации.
- FrameLevel() при первом вызове фиксирует центр/радиус исходной фигуры; при следующих восстанавливает старт с тем же центром/радиусом.
- Pivot, Distance, Yaw, Pitch и LevelRoot доступны только для чтения.

Единый владелец ввода — OrbitCamera с PointerGesture из [P3.4](pointer-input.md). Сборка вращается только после распознавания drag; горизонтальный delta изменяет yaw с обратным знаком, вертикальный — pitch с прямым. Корректное отпускание без drag выдаёт один Tapped. Rotate остаётся API без проверки UI, используемым диагностическим стендом; обычный ввод проходит PointerGesture. BoltSelection синхронизирует Transform физики перед лучом выбора. Проверочные точки после поворота вычисляются из локального центра шляпки через TransformPoint, не из ещё не обновлённого Collider.bounds.

## Проверка пользователем

1. Запустить EditMode → Screw.Tests.Levels.OrbitCameraTests: ожидаются 19 Passed. Проверяются смещённый относительно pivot центр геометрии, неизменность камеры/гравитации при вращении уровня, сохранение локальных Transform/масштаба, полные обороты, плавное прохождение полюсов, сброс/переворот, кадрирование и постоянный центр после изменения геометрии. Затем выполнить BootstrapScopeTests, LevelViewTests, LevelColliderTests и LevelPreparationTests.
2. Сохранив работу, выполнить BootstrapPipelineTests в PlayMode. Запустить из Bootstrap и напрямую из Gameplay: ожидается одна игровая камера без ошибок обязательных ссылок.
3. Перетаскиванием выполнить несколько полных оборотов сборки по горизонтали и вертикали в обе стороны и переворот. Камера, Ground и UI не вращаются; Model и Bolts остаются совмещены. Drag не снимает болт, зума и инерции нет. Проверить головки с разных сторон.
4. Повторить Stop/Play или перезагрузить Gameplay: стартовый ракурс должен совпасть при том же viewport. Изменить размер Game View: фигура остаётся целиком в кадре с запасом, текущие углы сохраняются.
5. На устройстве проверить движение одним пальцем после порога, отсутствие двойного движения от симуляции мыши, отмену при нескольких касаниях и удобство кадрирования. Перехват UI и отмену жеста проверить по инструкции P3.4.

Результаты проверок и статус приёмки ведутся только в индексе плана. Описание реализации не означает подтверждения Play Mode или устройства.
