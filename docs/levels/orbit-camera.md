# P3.3: орбитальная камера

[Индекс и приёмка](../development-plan/README.md) · [План P3](../development-plan/p3-world-and-input.md)

`Screw.Levels.OrbitCamera` находится на существующем экземпляре Main Camera в Gameplay. Ссылка Level Root назначена на Level_01 из LevelView через Unity MCP. Общий prefab Main Camera используется также в Bootstrap, поэтому компонент добавлен только на экземпляр Gameplay. Второй игровой камеры и новых зависимостей нет.

## Поведение

- Оба угла проходят полный круг без угловых ограничений. Камера свободно проходит через верхнюю и нижнюю точки и перевёрнутое положение. Двигается камера, трансформации уровня и гравитация не меняются.
- ЛКМ с перетаскиванием или один движущийся палец вращают камеру после порога 10 px. Движение на длину короткой стороны viewport соответствует 180°. Несколько касаний отменяют жест до отпускания всех пальцев; симуляция мыши не дублирует касание. UI и выход за viewport отменяют текущий жест.
- Автоповорота, инерции и пользовательского зума нет. Радиус сохраняется при вращении. При изменении соотношения сторон окна или FOV кадрирование пересчитывается для нового viewport.
- Start вызывает FrameLevel: центр орбиты и охватывающая сфера вычисляются из Renderer.bounds внутри назначенного Level Root, без Ground. Расстояние учитывает меньший горизонтальный/вертикальный угол обзора, near clip и коэффициент запаса Framing Padding = 1.15. Сфера сохраняет фигуру в кадре со всех ракурсов; это консервативное кадрирование с пространством под будущий UI.
- Стартовые углы сериализованы: yaw = 0°, pitch = 15°. Quaternion поворота камеры и её позиция сохранены в Gameplay. Runtime повторно рассчитывает старт по реальному viewport.
- ResetOrbit возвращает стартовые углы, центр и радиус первоначальной фигуры; при повторном вызове результат тот же. Bounds не уменьшаются вслед за удалёнными деталями. Повторная загрузка Gameplay заново вызывает FrameLevel для нового экземпляра.

FrameLevel требует перспективную камеру и хотя бы один Renderer уровня. Обязательная ссылка Level Root назначается явно. Runtime не ищет LevelView или камеру в сцене и не создаёт игровой контент.

## API для следующих задач

- Rotate(Vector2 deltaDegrees) применяет приращение обоих углов без ограничений. Yaw и Pitch нормализованы в диапазон [0, 360) только для численной устойчивости; это не останавливает вращение после полного круга.
- ResetOrbit() восстанавливает стартовую позу после инициализации.
- FrameLevel() заново определяет центр и радиус по назначенному уровню и восстанавливает старт.
- Pivot, Distance, Yaw, Pitch и LevelRoot доступны только для чтения.

Единый владелец ввода — OrbitCamera с моделью PointerGesture из [P3.4](pointer-input.md). Камера вращается только после распознавания drag, а корректное отпускание без drag выдаёт Tapped с экранной позицией. Сам Rotate остаётся методом вращения без проверки UI: сторонний код не должен обходить правила пользовательского жеста. [BoltSelection из P3.5](bolt-selection.md) обрабатывает Tapped и выбирает доступную головку; снятие болта подключается в P4.

## Проверка пользователем

1. Сохранить сцены. Запустить EditMode → Screw.Tests.Levels.OrbitCameraTests: ожидаются 18 Passed. Проверяются центр, неподвижность уровня/гравитации, полные обороты по обеим осям в обе стороны, плавное прохождение полюсов, сброс в том числе в перевёрнутую стартовую позу, кадрирование портретного/альбомного viewport и ошибки конфигурации. Затем выполнить BootstrapScopeTests, LevelViewTests и LevelColliderTests.
2. Сохранив работу, выполнить BootstrapPipelineTests в PlayMode. Запустить из Bootstrap и напрямую из Gameplay: ожидается одна игровая камера без ошибок обязательных ссылок.
3. Перетаскиванием выполнить несколько полных оборотов по горизонтали и вертикали в обе стороны. Проверить прохождение верхней/нижней точки без остановки или резкого разворота, включая перевёрнутую камеру. Зума и инерции нет. Фигура и Ground не вращаются, головки доступны для осмотра.
4. Повторить Stop/Play или перезагрузить Gameplay: стартовый ракурс должен совпасть при том же viewport. Изменить размер Game View: фигура остаётся целиком в кадре с запасом, текущие углы сохраняются.
5. На устройстве проверить движение одним пальцем после порога, отсутствие двойного движения от симуляции мыши, отмену при нескольких касаниях и удобство кадрирования. Перехват UI и отмену жеста проверить по инструкции P3.4.

Результаты проверок и статус приёмки ведутся только в индексе плана. Описание реализации не означает подтверждения Play Mode или устройства.

## Документация

API сверены через Context7 по официальному руководству Unity 2022.3: [Input на мобильных устройствах](https://docs.unity3d.com/2022.3/Documentation/Manual/MobileInput.html), [размер frustum, FOV и aspect](https://docs.unity3d.com/2022.3/Documentation/Manual/FrustumSizeAtDistance.html). Сигнатуры GetTouch и WorldToViewportPoint подтверждены reflection через Unity MCP. Расстояние до охватывающей сферы рассчитывается геометрически по её угловому радиусу.
