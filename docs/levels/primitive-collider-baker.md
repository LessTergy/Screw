# Подготовка внутренних примитивных коллайдеров в Editor

[План P4C](../development-plan/p4c-campaign.md)

По уточнению пользователя анализ меша разрешён только при подготовке в Editor. Сохраняются обычные примитивные Collider; анализа геометрии и генерации в runtime нет. Главное условие: весь объём каждого примитива остаётся внутри исходной геометрии, включая сохранение полостей. MeshCollider не используется даже как промежуточный анализатор.

## Подготовка через CoACD

Основные предложения формы даёт CoACD 1.0.14. Инструмент установлен в локальное окружение Python 3.12: NumPy 2.2.6 и SciPy 1.15.3. Установка и повторный запуск описаны в [Tools/Colliders](../../Tools/Colliders/README.md). Окружение и кэши `.tools/` не входят в Git и Unity-сборку. Целевое покрытие начинается с 90% при жёстком бюджете 15 боксов на деталь; незаполненные области дополняются крупными боксами из подтверждённого внутреннего объёма.

PrimitiveColliderBaker находится в сборке Screw.Editor, включённой только для Editor. Analyze(mesh, resolution, maxBoxes, minimumCoverage, surfaceInset, reduceCoverageToFit) возвращает Boxes в системе координат выбранной сетки, Rotation из неё в локальные координаты меша, число покрытых допустимых внутренних ячеек и выбранный TargetCoverage. Analyze по умолчанию строго требует заданное покрытие; BakePrefab включает адаптивное снижение цели. Локальная точка меша = Rotation * точка бокса. Исходные vertices/triangles не изменяются.

1. Проверить конечные координаты, трёхмерный объём и замкнутость/направление граней с объединением совпадающих позиций швов. Допускается стык одного длинного ребра с несколькими коллинеарными рёбрами противоположного направления; открытые границы отклоняются. Геометрия меша не достраивается.
2. Выбрать ориентацию по наименьшему bounding box среди исходных осей и направлений 12 крупнейших треугольников, нормализовать координаты и построить сетку. Это эвристика, не поиск глобального минимума. Отступ равен surfaceInset × минимальный габарит меша в выбранной ориентации; он задаётся с каждой стороны поверхности, включая стенки полостей. Треугольник проверяется против всего объёма ячейки по разделяющим осям с этим запасом. Ячейки защитного слоя исключаются из допустимой области и знаменателя покрытия по согласованному пользователем правилу.
3. Для связных областей оставшихся ячеек определить принадлежность внутреннему объёму через сумму телесных углов и ненулевой целочисленный winding. Пересечение согласованно ориентированных замкнутых оболочек остаётся внутри; полость, заданная внутренней оболочкой противоположного направления, остаётся пустой. Дробный неоднозначный winding отклоняется.
4. CoACD выполняет выпуклое разложение нормализованного меша. Используется seed 42 и ограничение количества частей. Раздельные оболочки обрабатываются отдельно в общем бюджете; вложенные оболочки остаются вместе, чтобы не заполнить полость. Выпуклые меши остаются данными офлайн-инструмента: компоненты MeshCollider не создаются. SciPy SLSQP вписывает бокс в каждую часть, максимизируя объём при ограничениях плоскостями её граней. Сохраняется лучший допустимый результат; не прошедшая ограничения итерация оптимизатора не используется.
5. Проверить бокс относительно исходного render mesh: центр должен быть внутри, а весь бокс, расширенный на отступ и численный запас, не должен пересекать ни один исходный треугольник. Подгонять грани до выполнения этого условия. Это консервативная проверка отступа от поверхности модели; каждый внутренний стык не уменьшается отдельно на 5%. Проверка всего объёма сохраняет и полости, полностью попавшие внутрь бокса.
6. На каждом шаге выбирать предложение CoACD либо наибольший свободный прямоугольный объём из целиком внутренних ячеек. Для последнего используется поиск максимального прямоугольника в срезах сетки; ячейки, пересекающие уже принятые боксы, исключаются. Предложения CoACD обрезаются относительно принятых боксов. Выбирается вариант с наибольшим приростом покрытия; при равенстве — с большим объёмом. Каждый принятый бокс повторно проверяется относительно исходных треугольников.
7. Остановиться, как только достигнут порог покрытия, либо исчерпан бюджет. Сначала использовать concavity threshold 0.05, затем 0.1 и 0.2 при недостаточном результате. Если цель не достигнута в бюджете, снижать её отдельно для каждой детали по 5 процентных пунктов: 90%, 85%, 80% и далее. Повторно использовать уже проверенный набор и удалить ненужные последние боксы; повторное разложение для каждого меньшего порога не требуется. Строгий Analyze вместо снижения выдаёт ошибку. Нулевая цель, внешний box или заполнение полости не допускаются.
8. При сборке общего prefab уменьшить каждый бокс на 0.0001 мировой единицы с каждой стороны для устойчивости к округлению координат. Через Physics.ComputePenetration устранить также проникновения между разными деталями обрезкой одной грани с наименьшей потерей объёма. После уменьшения и обрезки повторно проверить покрытие каждой детали и подобрать цель тем же шагом 5 пунктов. При отсутствии положительной достижимой цели prefab не сохранять. Ошибки геометрии и инструмента не обходятся снижением покрытия.

Параметры по умолчанию: resolution=24 по каждой оси, maxBoxes=15 на меш, minimumCoverage=0.9, surfaceInset=0.005 (0,5%). Общие значения заданы DefaultMaxBoxes, DefaultMinimumCoverage и DefaultSurfaceInset. surfaceInset=0 отключает отступ. Бюджет — верхний предел, а не обязательное количество. На отдельный CoACD-вызов приходится не более восьми начальных выпуклых частей; дополнительные боксы достраиваются по допустимому внутреннему объёму. Coverage означает долю центров подтверждённых внутренних ячеек после отступа, а не точный процент исходного объёма меша. Визуальное соответствие, тонкие края и контакты требуют оценки на настоящем уровне. Реализация использует только BoxCollider.

Результаты CoACD кэшируются отдельно от результатов подгонки. Изменение геометрии, параметров или версии подгонки меняет ключ. При холодной подготовке расчёт может занимать минуты; Editor-вызов отдельного процесса ограничен двумя минутами. Необработанные запросы можно рассчитать офлайн командой Tools/Colliders/Prepare.ps1 и повторить bake. Все изменения prefab агент выполняет через Unity MCP.

BakePrefab(path) сначала анализирует все подходящие MeshFilter. При ошибке одного из них prefab не сохраняется. При успехе создаёт дочерний _GeneratedPrimitiveColliders и сохраняет prefab через PrefabUtility. Повторный запуск заменяет только эту зарезервированную группу. По умолчанию существующие ручные Collider сохраняются, соответствующий меш пропускается. Для явно порученной замены ручного набора используется BakePrefab(path, minimumCoverage: 0.8f, replaceExisting: true): старые Collider удаляются только после успешного анализа всех частей, перед единственным сохранением. Пустые дочерние объекты старых коллайдеров удаляются; геометрия и прочие компоненты сохраняются. Rigidbody и runtime-компоненты не создаются. Для общего владельца формы нужно передавать prefab модели, а не копировать настройку в каждую сцену или вариант уровня.

Сохранение отклоняется при shear в иерархии или сочетании повёрнутой сетки с неравномерным масштабом: Unity BoxCollider не повторяет такое искажение. Ограничение подтверждено [официальной документацией Unity 2022.3](https://docs.unity3d.com/2022.3/Documentation/Manual/class-Transform.html).

Команда Editor: Tools → Screw → Levels → Bake Selected Model Colliders. В агентском процессе вызов и сохранение выполняются через Unity MCP; наличие Editor-команды не разрешает обход MCP другим каналом.

Физические контакты болтов и деталей отключены в LevelPartPhysics. При этом BoltSelection использует коллайдеры деталей как препятствия для луча: деталь не выбирается, но перекрывает болт сзади. Это разные механизмы; генератор не меняет ни матрицу контактов, ни правила выбора.
